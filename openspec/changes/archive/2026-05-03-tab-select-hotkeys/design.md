## Context

The keybinding editor iterates over `default_keybindings()` and skips any action where `action_to_name()` returns `None`. `SwitchToTab(u8)` intentionally returns `None` because it is parametric — there is no 1:1 TOML key name for it. As a result the nine Alt+1–9 tab-switching bindings are invisible to the editor and cannot be remapped.

The nine bindings are generated by a single `for i in 1..=9` loop in `default_keys.rs` using the hardcoded prefix `"M-"`. This is the natural seam to exploit: one configurable prefix → nine derived bindings.

## Goals / Non-Goals

**Goals:**
- One new TOML key (`switch_to_tab_prefix`) controls the modifier for all nine tab-switch bindings.
- The keybinding editor shows one row ("Switch to tab (1–9)") that the user can remap in capture mode.
- Override indicator, reset, and in-memory-immediate-apply all work the same as for normal bindings.
- Minimal diff — no new enums, no restructuring of `KeybindingConfig`.

**Non-Goals:**
- Allowing different modifiers per tab number.
- Showing nine individual rows.
- Supporting key combos that don't end in a digit (e.g. binding tab 3 to `F3`).

## Decisions

### D1 — Store the prefix as a raw string in TOML, not as a parsed key

`switch_to_tab_prefix = "M-"` (in `[keybindings]`) is a modifier-prefix string in the same notation used everywhere else (`M-`, `C-`, `C-M-`, etc.), **without** a trailing digit.

**Why not a full key combo?** A full combo (`M-1`) would require stripping the digit on every read, complicating round-trips. A bare prefix is always unambiguous.

**Alternatives considered:**
- Separate modifier + key fields — more fields, same expressiveness.
- Nine individual TOML keys — rejected in scope.

### D2 — Introduce a `PrefixBindingItem` variant on `KeybindingItem`

Rather than adding optional fields to the existing struct, add a second variant (a plain new struct `PrefixBindingItem`) and update the editor's item list to `enum EditorItem { Keybinding(KeybindingItem), Prefix(PrefixBindingItem) }`.

Wait — this risks a large refactor of the editor. **Simpler alternative:** re-use `KeybindingItem` with a sentinel `action_name = "switch_to_tab_prefix"`. The editor already dispatches on `action_name` for display; capture mode can detect this sentinel and strip the digit suffix from the pressed combo before saving.

**Decision:** use the sentinel approach. No new types, no enum wrapping.

### D3 — `default_keybindings()` receives the prefix as a parameter

Change signature to `default_keybindings() → KeybindingConfig` **and** add `default_keybindings_with_prefix(prefix: &str) → KeybindingConfig`. The no-arg version calls the parametric one with `"M-"`. Config load calls the parametric version with the stored prefix so that the "live" config already has the correct bindings.

**Why not mutate after loading?** Keeping the generation in one place (default_keys.rs) avoids scattered loop duplication.

### D4 — Capture mode: strip the digit from the captured combo

When capture mode fires for the `switch_to_tab_prefix` sentinel, the user presses e.g. `C-3`. The editor already has the raw `KeyCombo`. It formats it back to notation (`"C-3"`), strips the trailing digit, and stores `"C-"` as the new prefix. This is reliable because the tab-switch keys are always modifier+single-digit.

Pressing a combo without a trailing digit in capture mode shows an error: "Must end in a digit (e.g. Alt+1)".

### D5 — Saving and applying

On save, write `switch_to_tab_prefix = "..."` into `[keybindings]` in `~/.conduit/config.toml` using the existing `toml_edit` path. Then rebuild the nine `SwitchToTab` bindings in the live `KeybindingConfig` by clearing the old ones and re-running the loop.

The "reset to default" path removes the `switch_to_tab_prefix` key from TOML and restores `"M-"` bindings in memory.

## Risks / Trade-offs

- **Digit stripping is fragile for unusual notations** — e.g. a combo ending in `9` where 9 is not meant as a tab number. Mitigation: only strip in capture mode when the sentinel row is selected; normal bindings are unaffected.
- **Conflict detection skipped for prefix rows** — the nine derived bindings are not cross-checked against other actions. Mitigation: acceptable for now; tab-switch combos are structurally distinct (modifier+digit) and rarely collide.
- **`default_keybindings()` signature change** — callers of the no-arg form continue to work unchanged via the wrapper; only one new callsite (config load) uses the parametric form.
